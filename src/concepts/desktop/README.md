# Battle Augur desktop exploration 03

Lives in the existing design gallery as **Battle Augur · Desktop**. Select the desktop workflow to review Welcome and Roster editor, or Elements for component compositions.

Run `npm run dev`. Direct prototype links:

- `http://localhost:5173/?gallery=desktop` — separate desktop design library (Mobile/Desktop switch, independent view preferences)
- `http://localhost:5173/?desktop` — welcome and recent rosters
- `http://localhost:5173/?desktop=editor` — three-panel roster editor
- `?desktop=rosters`, `?desktop=lookup`, `?desktop=sources`, `?desktop=settings` — hub pages (draft)
- `?desktop=first-run` — no game data and no rosters yet
- add `&ambient=1` or `&ambient=0` to force the ambient gradient
- add `&theme=light` and `&scheme=<id>` (`default`, `crimson`, `gilded`, `azure`, `verdant`) to preview a theme on the standalone links

The desktop prototype uses synthetic, game-neutral Open Field data. It uses the shared theme tokens (`--ux-*` from `ux.css`), so light/dark and every colour scheme apply, plus T3's window/panel structure, and the launch-screen hierarchy of a code editor. Catalogue, roster and inspector use flat rows and dividers rather than cards.

Explore create, recent rosters, catalogue search and role filter, add/select/duplicate/remove units, collapse groups, edit model counts/equipment/upgrades/notes, Profile/Rules tabs, validation and over-budget states, panel toggles, light/dark appearance, and Command/Ctrl K or N. JSON import/export round-trips prototype rosters only. Dialogs contain keyboard focus and close with Escape.

Edits live for the prototype session and can be exported. The recent list contains fixed sample snapshots. This is a design prototype; it does not run the Battle Augur engine, install data, or persist workspace changes. Single-detachment editing is the scope of this first pass.

Gallery metadata: `src/design-data/roster-builder.design.json`. UI: `DesktopWorkbench.tsx`. Namespaced styles: `desktop.css`. Desktop screens retain their desktop frame in single-screen, workflow-board and Glance views; mobile concepts keep their existing frames.

Validation: `npm run build`, rendered visual checks at 1440px, and browser interaction checks for live budget updates, duplication/removal, profiles, validation, recent snapshots, create/empty state and gallery selection.

Revision 02 removes the title/search bar and bottom status strip. Panel controls float at the top right, workspace tabs sit at the top with rounded shapes, and the activity rail appears only on Welcome. Inspector tabs use the same rounded language.

Revision 03 puts the desktop on the shared themes: the root carries `ux-screen`, `light|dark` and `ux-scheme-*`, and `--dt-*` tokens map onto `--ux-*`. The gallery Display controls and the in-app Settings (theme, colour scheme) drive it. Panels become rounded cards on the canvas, roster groups are soft cards, and the roster header is gone: its name, budget, points limit, validation, data version and Export live in a hidable **roster summary popover** opened from the points button at the top right. While the popover is closed, a thin points line runs under the tabs.

Hub pages (draft for discussion): **Rosters** (search, needs-attention filter, system filter, sort, list with points/status/opened, detail pane with rename, duplicate, export, two-step delete), **Lookup** (search, scope chips, grouped units/rules/equipment, read-only entry with profile, conditional cost note and the rosters that use it), **Sources** (update banner and Update all, installed list with status chips and progress, source detail with update card, info, kept versions, factions, rosters using it, two-step remove; Add game data with collection, repository link and GitHub search), **Settings** (section nav; appearance, language, rosters, game data, storage, shortcuts, about). The activity rail shows on hub pages; the first tab follows the current hub page. Command/Ctrl comma opens Settings. Code: `DesktopPages.tsx`, `desktopData.ts`, `desktop-pages.css`.

Revision 03b: hub pages have no title header (buttons carry hints instead); page actions sit in the tab row at the top right. **Welcome** stays the landing page for a quick start; **Rosters** is for managing and finding rosters. Toasts split by kind: **functional** toasts (the result of the user's own action, optionally with Undo) appear top right under the tab row; **notifications** (background events such as a finished update) appear bottom right. Settings has editable **Key bindings** (record, conflict with Replace, per-row and full reset; a binding needs ⌘ or ⌥; saved in local storage) and the app's shortcuts follow them. Colour schemes use the app's names: Default, Crimson, Gilded, Azure, Verdant.

Revision 04: panels reach the window edges. The catalogue and inspector sit on the window canvas; the centre (and every hub page) is one sheet whose corners are rounded only where it does not touch the window border. The side panels resize (drag, arrow keys with Shift for bigger steps, double-click to reset) and their content adapts through container queries. A gallery Display switch, **Ambient gradient**, toggles a blurred theme-coloured gradient in the top-left of the canvas (saved locally; `&ambient=` on standalone links).

New flows: **installs and updates** run as shared jobs. A progress button appears in the tab row and opens a jobs panel with steps, a faction picker when an install needs you, Cancel (no confirmation) and Hide. Finished jobs raise a notification with View. **Guided creation** is one dialog with a step list (game system, points limit with presets/custom/unlimited, faction and force, configuration, name with a suggestion); earlier steps stay editable and Skip guided setup creates with defaults. **First run** (`desktop-first-run`): Welcome offers the collection to install, then "Create your first roster"; Rosters shows an empty state. Code: `DesktopJobs.tsx`, `DesktopCreate.tsx`, `WelcomeStart` in `DesktopPages.tsx`.

Revision 05 · Sources flows: the Sources page's detail pane gains sub-views, kept in the page's selection so they survive switching pages (`report:<id>`, `collection:<id>`, `github`), each with a Back link. A finished update leaves a **last update card** on the source (updated when, from and to which version, roster check line) with Check rosters, a progress bar and Cancel while checking, and View report; a finished check raises a notification with View report. The **update report** shows roster chips (rosters, unchanged, changed, faction removed), changed rosters as cards with their tag, change lines and Open, unchanged rosters, and data changes as added/changed/removed counts with two examples each and Show all; "No rosters changed" when nothing changed. **Add game data** lists the default collection's supported sources with Show all, which opens the **collection page**: search (from six sources), rows with Supported / Installed / Update / Archived chips and an action (Install, Installed, Update, Installing n%, Choose factions; installs use the shared jobs), Show archived (n), nested libraries and collections, and a ⋯ menu (Refresh, Copy link, Hide collection for the default one, Remove collection for saved ones, both with Undo). **Search GitHub** searches on Enter, with prompt, results (updated date, archived chip, install action), archived results behind the toggle, no results and an error with Retry. **Add a collection or library** is a dialog: link, Find, a preview (name, maintainer, number of sources), Add collection opens the new page; a repository link offers Install it instead; duplicates and other links get an inline error. States that clicks cannot reach (offline copy, refresh failed, loading, empty, check failed, no connection) sit under a collapsed **Preview states** control at the bottom of each view. Code: `DesktopSourceFlows.tsx`, `desktop-sources.css`; sample data at the end of `desktopData.ts`.
