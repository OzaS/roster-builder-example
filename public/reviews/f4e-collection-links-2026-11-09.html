Which link is which?
Repository: one project on GitHub. If it holds game data, you install it. If it has a collection file, we find it.
Collection: a list of repositories someone keeps (a .json file). Adding it shows all of them.
Organisation or user: everyone's repositories under one GitHub name (github.com/name).
Found game data but no collection? Tap Install it when the app offers it. You don't need a collection to install.

Behaviour (shared, app-core + sources; one owner)

  • Repository link (github.com/o/r, o/r, …/tree/<branch>): one GitHub request lists the repository root on the given branch, or the default branch if none is given. Up to 5 .json files under the collection size limit are downloaded from raw and checked by the worker's existing collection validator. collection.json comes first, then by name. Subfolders are not searched.
  • 1 match → preview with “Found in …” and saved as the raw file link on that branch (follows the branch, like today's file links). Duplicate checks use the existing collectionKey, so a repository link and the file link of the same collection count as one.
  • Several → choose one, then preview. None, but .gst/.cat files → game-data notice with Install it (the current install path). None and no game data → error with Search for data / Guide. Nothing is saved on Cancel or on an error.
  • Search for data opens the system browser through the existing host link opener: https://www.google.com/search?q= + "{system}" BattleScribe data site:github.com (empty name → without the quoted part). Nothing searches automatically, game names never appear in code (the user types the name), and nothing is curated.
  • Mobile moves its own copy of the add logic onto app-core's createCollectionAdd (desktop already uses it), so phone, tablet and desktop share one flow and one set of strings.
