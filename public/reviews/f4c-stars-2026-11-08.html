Desktop: catalogue, New roster dialog, Add force dialog

With a mouse the outline star appears only on the hovered or keyboard-focused row, so the 200 px minimum catalogue does not lose width. Filled stars always show. The star is its own Tab stop before the row's Add, and Edit › Star unit toggles the focused catalogue row. It has no default key (⌘D is already Duplicate unit), and users can set one in Key bindings.

Behaviour (every platform, one shared app-core implementation)

  • What can be starred: factions (catalogues) in New roster and Add force; force entries in Add force; units in the Add unit sheet / catalogue pane / desktop catalogue. Stored on the device by game system + kind + entry id, so a unit star also applies in other rosters of the same system. It survives a restart, is not part of the roster file and is not an Undo step.
  • Order: starred rows go first in the order the data gives them, and keep their state (Slot full, quota chip, unavailable Add, hidden). Units move into the Starred group and are not listed twice.
  • No stars yet: the lists look as they do now, with no empty Starred group and no hint. The outline stars (touch) or the hover star (desktop) are how users find the feature.
  • Stale stars (the entry is gone after a data update or the source was removed): left out of the lists without a message, and kept, so they come back if the entry returns.
  • Read-only rosters: there is no catalogue, so no unit stars; faction stars in New roster work as usual.
  • Accessibility: the button reads "Star Line Infantry" / "Unstar Line Infantry" with a selected state, and VoiceOver/TalkBack announce "Starred". The filled star uses the accent colour, not the warning amber that already means "Slot full".
